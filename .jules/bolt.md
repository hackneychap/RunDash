## 2025-02-18 - [SQLite Query Optimization for Garmin Data Sync]
**Learning:** The application syncs run activities from a local GarminDB SQLite database, which previously transferred thousands of old records into Python memory only to discard them based on a 2-year cutoff. Furthermore, date parsing using `strptime` is significantly slower compared to `fromisoformat`.
**Action:** When querying large local SQLite databases (like GarminDB), push down WHERE clauses to filter large datasets at the database level instead of in-memory. For date string parsing, use string slicing and `datetime.date.fromisoformat` over `datetime.datetime.strptime` where the string format allows (e.g., extracting "YYYY-MM-DD" from "YYYY-MM-DD HH:MM:SS").
## 2025-02-18 - [Django Caching with Dynamic Timeouts & Bulk Operations]
**Learning:** When caching context with date-dependent elements (like 'today' vs 'last week'), setting a static cache timeout can serve stale data if the cache boundary crosses midnight. Furthermore, when syncing data via Django's `bulk_create` and `bulk_update` methods, the standard `post_save` and `post_delete` signals are bypassed, meaning cache invalidation must happen explicitly.
**Action:** Use a dynamic cache timeout calculating seconds until midnight via `django.utils.timezone.localtime()` instead of static durations, ensuring time calculations are timezone-aware. Explicitly call `cache.delete('key')` after large bulk operations complete to maintain cache coherence, while utilizing signals for standard individual record modifications.
